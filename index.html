Optional: find your starting point

Try these without looking anything up. “No idea” is useful. Skip them if you prefer to begin at lesson 1.

The model asks to save a file. Which program must execute that operation?

The application or a provider-owned tool service, depending on the architecture. See lesson 1.

The same tool request arrives twice after a timeout. Is executing both always safe?

No. Side effects and uncertain outcomes need a recovery policy. See lesson 5.

Why might two conversations need separate session state?

To select the right context and avoid accidental mixing. This does not replace access control. See lesson 7.

Why can a longer input delay the first answer token?

Input processing and other waiting can increase. See lesson 9.

Why can memory grow while the model weights stay unchanged?

Per-sequence caches and runtime work can grow. See lesson 10.

A cheaper call fails more often. Which denominator helps compare useful cost?

Successful tasks meeting the same criteria. See lesson 15.

What the course does and does not run

All 15 lessons are available. The browser experiments are explicitly simplified models. They make no live model calls and require no account.

Labs provide worked code or observable procedures where appropriate. Hosted calls, Pi/OpenClaw runtime exercises, and GPU benchmarks must be run in your own lab; the course does not claim measured results for them.

Each page includes supporting sources, assumptions, hidden-answer checks, and a What I did not trace section. The project remains HTML only.
