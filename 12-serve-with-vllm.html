Weights are the model’s stored learned numbers. A generation cache retains working data for an active request. GiB is a memory unit equal to 1,073,741,824 bytes. Anthropic Messages and chat completions are two request formats. A protocol adapter translates requests and responses between formats.

Inference engine: software that executes model computation.

Endpoint: a network address accepting a defined request format.

Adapter: code that translates the application’s model interface.

The model becomes a service you operate

A hosted provider hides most inference operations behind its interface. When you self-host, you choose the model files, engine version, hardware, launch arguments, and capacity limits. Your assistant still needs validated tools and evidence checks. A running model server does not supply those application rules.

vLLM exposes a model-serving interface compatible with common chat-completion requests. That lets an adapter reuse the application’s higher-level task logic. A protocol is an agreed message format and exchange. For example, one API places instructions in a top-level system field, while another uses a system-role message. Returned text blocks and choices also need translating. Compatibility does not establish identical model behavior or universal tool support. Test how messages are packaged, why generation stops, and whether partial output arrives as it is produced. If you use tools, also test the parser: code that converts model output into structured tool requests.

Start with a small instruction model and one request on a supported environment. The worked command uses a model named in current vLLM documentation. It is a plumbing exercise, not a claim that the model matches the quality of your hosted baseline.

Budget capacity before increasing concurrency

Suppose a teaching server has 24 GiB of available memory. Allocate 8 GiB to weights and 2 GiB to overhead. If each active request needs 1 GiB of cache, fourteen such requests fit the remaining allowance in this simplified calculation.

The demo lets you change those allocations and the number of incoming requests. It reports how many cache slots fit, not how many real requests an engine guarantees to admit. Real allocations include working memory, engine reservations, cache blocks, and workload-dependent behavior. Memory admission is only one constraint; compute capacity can become the limit first.

For a remote GPU host, run the server on that host and use a controlled connection from your application. Localhost addresses in the example mean the machine running the command. Do not assume a phone’s localhost points to your GPU. Record the exact model revision and installed versions before comparing results.

Two ways to picture it

Operating inference resembles running your own database service. A reachable port is only the beginning; capacity and query correctness remain separate.

It also resembles owning a workshop rather than ordering finished parts. You gain control, but the analogy does not predict whether ownership is cheaper.

Work it out

For a 24 GiB allowance: 24 − 8 − 2 = 14 GiB of cache headroom. At 1 GiB per request, fourteen cache slots fit. Sixteen incoming requests leave two waiting in the teaching model.

Hands-on milestone · run in your own lab

Apply it to the document assistant

  1. Choose a supported Linux GPU environment using the current installation guide. Record driver and engine versions.
  2. Install vLLM in an isolated environment. Run the small-model server below on that GPU host.
  3. From the same host, request the model list and send the worked chat request.
  4. Write a protocol adapter for your document assistant. Repeat the fixed evaluation set before increasing concurrency.
Worked code or commands
# On a supported GPU host after installing vLLM:
vllm serve Qwen/Qwen2.5-1.5B-Instruct --host 127.0.0.1 --port 8000
# In another terminal on that same host:
curl http://127.0.0.1:8000/v1/models
curl http://127.0.0.1:8000/v1/chat/completions   -H 'Content-Type: application/json'   -d '{"model":"Qwen/Qwen2.5-1.5B-Instruct","max_tokens":64,"temperature":0,"messages":[{"role":"user","content":"policy-v1: Returns within 30 days. State the window and cite policy-v1."}]}'
# Keep the initial server loopback-only; arrange a controlled tunnel for remote access.

Can you use the idea elsewhere?

A server returns HTTP 200 with an unsupported answer. Did the task succeed?

No. Transport success and application correctness differ.

The weights fit exactly into memory. Is there room for generation?

Not necessarily. Account for cache and other runtime allocations.

The server accepts basic chat. Does that prove its tool parser works for your model?

No. Verify tool requests and result pairing with that model and engine configuration.
