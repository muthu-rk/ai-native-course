Reuse machinery without losing responsibility

You now have a small loop you can explain. That makes a reusable runtime easier to evaluate. Instead of asking whether a framework can do everything, map each responsibility to an owner. Keep the same corpus, meaning your document collection, and evaluation questions while changing the machinery.

The Pi repository separates a model interface for different providers, an agent runtime, and a coding application. You can study the reusable layers without building a coding assistant. Your document search remains a normal application function, connected through the runtime’s tool interface.

In the inspected source, the loop validates arguments before beforeToolCall can block execution. This hook is a callback your application supplies before the operation runs. For example, a string document ID can pass validation but fail your caller-access check. The hook provides a place to enforce an application policy. It does not know that policy for you. The inspected default allows parallel tool execution; an application that requires order must choose and test its execution policy.

Compare responsibility rather than line count

Use the responsibility sorter before reading its feedback. Model-call coordination belongs to the runtime in this exercise. Deciding whether a passage supports a claim belongs to your application. Retention rules for saved drafts also remain an application decision, even if a library offers storage primitives.

Fewer lines of handwritten code can remove defects, but the number of removed lines is not a correctness measure. Compare observable behavior. Does a denied read still stop? Does a timeout remain an error? Does the same source identifier appear in the final answer?

Subscribe to events so one model call and one tool execution are visible in your trace. An event is evidence about the runtime’s control flow, not proof of the content’s truth. Keep a small provider adapter at the boundary so changing a model does not require rewriting evidence checks.

Two ways to picture it

A runtime resembles a web framework: routing machinery can be reused, while business authorization stays specific to the application. Framework defaults still need inspection.

It also resembles a vehicle’s transmission. It coordinates motion, but it does not choose a safe destination. Mechanical determinism is the analogy’s limit.

Hands-on milestone · run in your own lab

Apply it to the document assistant

  1. Create a separate lab folder with npm init -y.
  2. Install @earendil-works/pi-agent-core, @earendil-works/pi-ai, typebox, and tsx. Record installed versions.
  3. Set ANTHROPIC_API_KEY and MODEL_ID locally. Save the example as pi-lab.ts; run npx tsx pi-lab.ts.
  4. Reuse the readDocument policy from lesson 3 and the 20-case notebook from lesson 2. Start with allowed, denied, and missing-evidence cases.
Worked code or commands
// API shape checked against Pi main on 26 October 2026; record your installed versions.
import { Agent } from "@earendil-works/pi-agent-core";
import { createModels } from "@earendil-works/pi-ai";
import { anthropicProvider } from "@earendil-works/pi-ai/providers/anthropic";
import { Type } from "typebox";
const models = createModels();
models.setProvider(anthropicProvider());
const model = models.getModel("anthropic", process.env.MODEL_ID!);
if (!model) throw new Error("Model is not in this provider catalog");
const agent = new Agent({
  initialState:{model, systemPrompt:"Use read_policy for return-window questions.", tools:[{
    name:"read_policy", label:"Read policy", description:"Read the return policy",
    parameters:Type.Object({}),
    execute:async () => ({content:[{type:"text",text:"policy-v1: Returns within 30 days."}],details:{}})
  }]},
  streamFn:models.streamSimple.bind(models), toolExecution:"sequential"
});
agent.subscribe(event => { console.log(event.type); });
await agent.prompt("What is the return window? Cite the policy.");

Can you use the idea elsewhere?

Pi emits a successful tool-end event. Is the answer verified?

No. The event records an operation result; application evidence checks remain necessary.

Two writes must occur in order. Can you rely on a parallel default?

No. Select and test ordered execution, including failure behavior.

You switch the provider adapter. Should document access policy change automatically?

No. Preserve the domain policy and verify it still runs at the new boundary.
